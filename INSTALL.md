# Установка с нуля

Всего нужно получить четыре значения: два от Телеграма и два от Яндекса.
Займёт минут пятнадцать.

| Что | Где взять | Пример |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | @BotFather → `/newbot` | `8123456789:AAH...` |
| `TELEGRAM_ALLOWED_USERS` | @userinfobot → пришлёт ваш ID | `123456789` |
| `Y360_TOKEN` | oauth.yandex.ru → приложение → токен | `y0_AgAAAAA...` |
| `Y360_ORG_ID` | `docker compose run --rm cli orgs` | `1234567` |

---

## Шаг 1. Токен бота

1. В Телеграме напишите [@BotFather](https://t.me/BotFather), команда `/newbot`.
2. Он спросит **название** (любое, например «Почта компании») и **username** —
   он должен заканчиваться на `bot`, например `romashka_hr_bot`.
3. В ответ придёт строка вида `8123456789:AAHdqTcvC...` — это `TELEGRAM_BOT_TOKEN`.

Никаких дополнительных настроек у BotFather делать не нужно: команды бот
регистрирует сам при первом запуске.

## Шаг 2. Ваш Telegram ID

Напишите [@userinfobot](https://t.me/userinfobot) — он ответит числом вида
`123456789`. Это `TELEGRAM_ALLOWED_USERS`.

Если админов несколько — перечислите через запятую: `123456789,987654321`.
Все, кто не в списке, получат от бота отказ.

> ID нужен именно до первого запуска: бот выдаёт пароли и без белого списка
> не стартует. Команда `/id` в самом боте тоже работает и отвечает даже тем,
> у кого доступа нет, — удобно добавлять коллег потом.

## Шаг 3. Токен API 360

Здесь два действия: зарегистрировать приложение и получить для него токен.

### 3.1. Приложение

1. Откройте [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new).
2. Тип — **приложение для авторизации пользователей** (не «доступ к API без
   пользователя»): нам нужен токен, действующий от имени администратора.
   Тип нельзя изменить после создания.
3. Название — любое, например «Бот кадровика».
4. Платформа — **Веб-сервисы**, Redirect URI —
   `https://oauth.yandex.ru/verification_code`.
5. Права — найдите в списке **API Яндекс 360 / Directory API** и отметьте:
   - `directory:read_users` — чтение сотрудников;
   - `directory:write_users` — создание, блокировка, пароли, удаление;
   - `directory:read_departments` — отделы;
   - `directory:read_organization` — чтобы команда `cli orgs` показала ID
     организации (не обязательно, но экономит время на шаге 4).
   - `ya360_security:audit_log_mail` — для команды `/dead`, которая ищет
     неиспользуемые ящики (можно добавить позже, но тогда придётся
     выпустить токен заново).
6. Сохраните. На странице приложения появится **ClientID**.

> Если под рабочим аккаунтом на вашем домене приложение создать не даёт —
> зарегистрируйте его под личным Яндекс-аккаунтом. Это не помешает: права
> токена определяет тот, кто будет **авторизовываться** на следующем шаге,
> а не тот, кто создал приложение.

### 3.2. Токен

1. Выйдите из всех аккаунтов Яндекса или откройте окно в режиме инкогнито.
2. Войдите под **администратором организации** — тем аккаунтом, под которым
   вы заходите в admin.yandex.ru.
3. Откройте ссылку, подставив свой ClientID:

   ```
   https://oauth.yandex.ru/authorize?response_type=token&client_id=ВАШ_CLIENT_ID
   ```

4. Нажмите «Разрешить». Токен появится на странице и продублируется в адресной
   строке после `access_token=` — до символа `&`. Начинается с `y0_`.
5. Скопируйте сразу: второй раз Яндекс его не покажет.

Токен живёт около года. Когда протухнет, бот начнёт отвечать `HTTP 401` —
просто пройдите шаг 3.2 заново, приложение пересоздавать не надо.

## Шаг 4. ID организации

Заполните в `.env` всё, кроме `Y360_ORG_ID`, и спросите у API:

```bash
docker compose run --rm cli orgs
```

Выведет строку вида `1234567  ООО Ромашка` — число и есть `Y360_ORG_ID`.

Если права `directory:read_organization` вы не выдали, API ответит отказом.
Тогда ID можно увидеть в адресной строке [admin.yandex.ru](https://admin.yandex.ru)
при переходе по разделам (параметр `org=`) или спросить в поддержке Яндекс 360.

## Шаг 5. Заполнить .env

```bash
cp .env.example .env
nano .env
```

Минимально нужны пять строк, остальное можно не трогать:

```ini
TELEGRAM_BOT_TOKEN=8123456789:AAHdqTcvC...
TELEGRAM_ALLOWED_USERS=123456789
Y360_TOKEN=y0_AgAAAAA...
Y360_ORG_ID=1234567
Y360_DOMAIN=romashka.ru
```

Полезно сразу задать:

```ini
# отдел по умолчанию, если в сообщении он не указан
BOT_DEFAULT_DEPARTMENT=Все сотрудники
# удалять сообщение с паролем из чата через 2 минуты
BOT_AUTO_DELETE_SECONDS=120
# кнопку удаления сотрудника лучше включать осознанно
BOT_ALLOW_DELETE=false
# хранить выданные пароли, чтобы позже посмотреть их в карточке сотрудника
BOT_STORE_PASSWORDS=true
```

## Шаг 6. Запуск

```bash
docker compose up -d --build
```

```bash
docker compose logs -f bot
```

В логе должно появиться `Бот @имя_бота запущен. Организаций: 1, доступ у 1 пользователей`.

Проверьте в Телеграме по порядку:

1. `/id` — бот отвечает вашим ID и «Доступ: есть».
2. `/dept` — список отделов. Если он пришёл, значит токен и ID организации верные.
3. `Тестов Тест` — заведите сотрудника и убедитесь, что почта и пароль пришли.
   Потом откройте его через `/find Тестов` и заблокируйте.

## Nginx Proxy Manager и порты

Делать в NPM ничего не нужно. Бот работает по long polling: сам открывает
исходящее HTTPS-соединение к `api.telegram.org` и ждёт сообщений. Он не слушает
ни одного порта, не занимает 80/443 и не требует домена или сертификата —
проксировать нечего. Ваши существующие сайты в NPM он никак не затрагивает.

Firewall тоже не трогаем: нужны только исходящие соединения на 443,
они открыты по умолчанию.

## Обновление

```bash
git pull && docker compose up -d --build
```

Данные (`data/`) и настройки (`.env`, `config/orgs.json`) при пересборке не
затрагиваются.

Код лежит внутри образа, поэтому после `git pull` контейнер обязательно
пересобрать — без `--build` продолжит работать старая версия. Это же касается
разовых команд: `docker compose build cli` перед `docker compose run --rm cli …`
(или сразу `docker compose run --rm --build cli …`, если ваша версия Compose
поддерживает этот флаг).

## Если что-то не так

Сначала запустите самопроверку — она пройдёт по шагам и скажет, где споткнулось:

```bash
sudo docker compose build cli && sudo docker compose run --rm cli check
```

Она проверит формат токена, покажет, какому аккаунту он принадлежит (должен быть
администратор организации), попробует получить список организаций и достучаться
до отделов и сотрудников вашей.

| Симптом | Причина и что делать |
|---|---|
| `Не задано Y360_TOKEN` при старте | `.env` не создан или лежит не рядом с `docker-compose.yml` |
| `TELEGRAM_ALLOWED_USERS пуст` | не заполнен белый список — бот намеренно не стартует |
| Бот молчит на любые сообщения | не тот `TELEGRAM_BOT_TOKEN`; проверьте `docker compose logs bot` |
| «Нет доступа» в ответ на ФИО | ваш ID не в `TELEGRAM_ALLOWED_USERS`; узнайте его командой `/id` |
| `Network is unreachable` к api.telegram.org | Телеграм недоступен с этого сервера: пропишите `TELEGRAM_PROXY` или разверните бота на VPS без блокировки |
| `Permission denied: data/...` | каталог данных принадлежит другому пользователю: `sudo chown -R 10001:10001 data` (контейнер работает под uid 10001) |
| `HTTP 401` от API | токен протух или отозван — повторите шаг 3.2 |
| `HTTP 403` от API | токен получен не под администратором организации либо не выданы права `directory:write_users` |
| `HTTP 404` от API | неверный `Y360_ORG_ID` |
| «Отдел не найден» | посмотрите точные названия через `/dept` |
| Не создаётся сотрудник, ошибка про nickname | логин занят алиасом или общим ящиком — задайте логин вручную: `Иванов Иван` создаст `ivan.ivanov`, а `/find` покажет, кто уже занимает адрес |

Логи за последний час:

```bash
docker compose logs --since 1h bot
```
