# Яндекс 360 — телеграм-бот администратора

Заводит сотрудников, ищет их, блокирует, сбрасывает пароли, удаляет и хранит архив
счетов. Работает с несколькими организациями. Разворачивается на VPS одной командой
`docker compose up -d`.

```
Вы:  Петрова Мария | Бухгалтерия | Бухгалтер
Бот: Петрова Мария · Логин: maria.petrova · Отдел: Бухгалтерия
     [✅ Создать]  [✖️ Отмена]

Бот: ✅ Петрова Мария
     Почта:  maria.petrova@вашдомен.ru
     Пароль: 7hK$eRm2xPqv
     Пароль нужно сменить при первом входе.
```

Поверх [API 360](https://yandex.ru/dev/api360/doc/ru/) (`api360.yandex.net/directory/v1`).
Зависимость одна — `requests`.

## Возможности

**Заведение сотрудника** — отправьте ФИО, бот покажет, что получится, и создаст после
подтверждения:
- логин транслитерацией по паспортным правилам (`Щербакова → shcherbakova`),
  шаблон настраивается: `ivan.ivanov`, `iivanov`, `ivanov`;
- однофамильцу выдаст `ivan.ivanov2` — сверяется с существующими логинами и алиасами;
- пароль через `secrets`, без похожих символов `0/O/1/l`, со сменой при первом входе;
- отдел ищется по названию: `| Продажи |` найдёт «Отдел продаж», ID помнить не нужно.

**Карточка сотрудника** (`/find Иванов`) — почта, алиасы, отдел, должность, статус,
и кнопки:
- 🔒 **Заблокировать / Разблокировать** — вход закрыт, почта и файлы сохранены;
- 🔑 **Новый пароль** — генерирует и присылает, со сменой при входе;
- 🗑 **Удалить** — выключено по умолчанию; включается флагом `allow_delete`
  и требует набрать `удалить <логин>` вручную.

**Несколько организаций** — `/org` переключает; у каждой свой токен, домен, шаблон
логина и правило удаления. Выбор запоминается для каждого чата.

**Счета** — `/bill` даёт ссылку на раздел оплаты в админке и архив документов.
Пришлите боту PDF счёта — он сохранит его в архив своей организации и вернёт по кнопке.
*Автоматически выгружать счета нельзя: в API 360 нет методов биллинга — только
сотрудники, отделы, группы, домены и почтовые настройки.*

**Журнал** `data/journal.csv` — кто, когда, в какой организации и что сделал
(создал, заблокировал, сменил пароль, удалил). Пароли по умолчанию не пишутся.

**Белый список** — бот отвечает только ID из `TELEGRAM_ALLOWED_USERS`, без него не
запускается вовсе.

**CLI** для массовых операций: заливка сотрудников из CSV, выгрузка всех в CSV,
блокировка списком.

## Установка на VPS

Подробно, с картой «что где брать» — [INSTALL.md](INSTALL.md). Кратко:

```bash
git clone <адрес-репозитория> ya360-bot && cd ya360-bot
```

```bash
cp .env.example .env && nano .env
```

```bash
docker compose up -d --build
```

Логи и перезапуск:

```bash
docker compose logs -f bot
```

Контейнер поднимается сам после перезагрузки сервера (`restart: unless-stopped`)
и переживает обрыв сети — long polling переподключается сам, входящий порт и белый
IP не нужны.

Локально без Docker: `pip install -r requirements.txt && python bot.py`.

## Что заполнить в .env

### 1. Токен API 360

1. На [oauth.yandex.ru](https://oauth.yandex.ru) под аккаунтом **администратора
   организации** создайте приложение (redirect URI — `https://oauth.yandex.ru/verification_code`).
2. Права: `directory:read_users`, `directory:write_users`, `directory:read_departments`.
3. Откройте `https://oauth.yandex.ru/authorize?response_type=token&client_id=ВАШ_CLIENT_ID`
   — токен будет в адресной строке после `access_token=`. Второй раз его не покажут.

### 2. ID организации

```bash
docker compose run --rm cli orgs
```

Если API не отдаёт список — ID виден в [админке](https://admin.yandex.ru) в адресной
строке раздела «Компания».

### 3. Бот

`@BotFather` → `/newbot` → токен. Свой Telegram ID — у `@userinfobot` или отправьте
боту `/id`, он ответит даже без доступа.

## Несколько организаций

Скопируйте `config/orgs.example.json` в `config/orgs.json` — переменные `Y360_*` из
`.env` тогда не нужны:

```json
{
  "orgs": [
    {
      "key": "romashka",
      "name": "ООО Ромашка",
      "org_id": "1234567",
      "token": "y0_AgAAAAA...",
      "domain": "romashka.ru",
      "nickname_pattern": "{first}.{last}",
      "allow_delete": false
    },
    {
      "key": "vtoraya",
      "name": "ИП Иванов",
      "org_id": "7654321",
      "token": "$IVANOV_TOKEN",
      "nickname_pattern": "{f}{last}",
      "allow_delete": true
    }
  ]
}
```

`"token": "$IVANOV_TOKEN"` — значение возьмётся из переменной окружения, чтобы не
держать токены в файле. У каждой организации свой токен: он выдаётся администратором
конкретной организации.

## Команды бота

| Сообщение | Что делает |
|---|---|
| `Иванов Иван` | завести сотрудника в отдел по умолчанию |
| `Иванов Иван Иванович` | с отчеством |
| `Иванов Иван \| Продажи \| Менеджер \| +79990000001` | отдел, должность, телефон |
| `/find Иванов` | карточка: блокировка, пароль, удаление |
| `/dept` | отделы с ID |
| `/org` | переключить организацию |
| `/bill` | оплата и архив счетов |
| файл PDF | сохранить счёт в архив |
| `/id` | ваш Telegram ID |

## Массовые операции (CLI)

CSV Excel-совместимый: шапка на русском или английском, разделитель `;` или `,`
(образец — [examples/users.csv](examples/users.csv)):

```csv
Фамилия;Имя;Отчество;Отдел;Должность;Телефон;Логин;Алиасы
Иванов;Иван;Иванович;Отдел продаж;Менеджер;+79990000001;;
Петрова;Мария;Сергеевна;Бухгалтерия;Бухгалтер;+79990000002;;buh
```

Пустой «Логин» — сгенерируется из ФИО, пустой «Пароль» — сгенерируется.

```bash
docker compose run --rm cli create -f examples/users.csv --dry-run
```

```bash
docker compose run --rm cli create -f examples/users.csv -o data/new.csv
```

Файл результата (`data/new.csv`, открывается в Excel) содержит статус, почту и пароль
по каждой строке — его и раздаёте, потом удаляете.

```bash
docker compose run --rm cli export -o data/users.csv
```

```bash
docker compose run --rm cli disable ivan.ivanov maria.petrova
```

Для нескольких организаций добавьте `-O ключ`, например `cli -O vtoraya dept`.
Без Docker те же команды: `python -m y360 export -o data/users.csv`.

## Безопасность

- `.env`, `config/orgs.json`, `data/` в `.gitignore`. Токен API 360 даёт полный доступ
  к сотрудникам организации — храните как пароль администратора.
- Бот отвечает только из белого списка; остальным — отказ и запись в лог.
- `BOT_AUTO_DELETE_SECONDS=120` — сообщение с паролем самоуничтожится в чате
  (в уведомления пароль всё же попадёт, это не панацея).
- Удаление сотрудника необратимо: пропадают почта и Диск, восстановить нельзя.
  Поэтому оно выключено по умолчанию, требует подтверждения текстом и пишется в журнал.
  В большинстве случаев нужна блокировка.
- Контейнер работает под непривилегированным пользователем и пишет только в `/app/data`.

## Структура

```
bot.py                 бот: маршрутизация, карточки, счета, подтверждения
y360/api.py            HTTP-клиент API 360: ретраи, 429, пагинация
y360/orgs.py           реестр организаций и их настроек
y360/service.py        отделы, уникальные логины, создание сотрудника
y360/names.py          транслитерация и генерация паролей
y360/state.py          что помнит бот между перезапусками
y360/telegram.py       клиент Bot API: long polling, файлы
y360/csvio.py          CSV с русскими шапками и BOM для Excel
y360/cli.py            orgs / dept / export / create / disable
tests/test_offline.py  проверки без обращения к API
```

```bash
python tests/test_offline.py
```

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | токен от @BotFather |
| `TELEGRAM_ALLOWED_USERS` | — | ID тех, кому можно пользоваться ботом |
| `Y360_TOKEN`, `Y360_ORG_ID` | — | одна организация (иначе `config/orgs.json`) |
| `Y360_ORG_NAME`, `Y360_DOMAIN` | — | как называть организацию и её домен |
| `Y360_NICKNAME_PATTERN` | `{first}.{last}` | шаблон логина: `{first} {last} {f} {l}` |
| `Y360_PASSWORD_LENGTH` | `14` | длина пароля (10–20) |
| `Y360_PASSWORD_CHANGE_REQUIRED` | `true` | смена пароля при первом входе |
| `BOT_DEFAULT_DEPARTMENT` | корневой | отдел, если не указан в сообщении |
| `BOT_ALLOW_DELETE` | `false` | кнопка удаления сотрудника |
| `BOT_AUTO_DELETE_SECONDS` | `0` | удалять сообщение с паролем через N секунд |
| `BOT_LOG_PASSWORDS` | `false` | писать пароли в журнал |
| `DATA_DIR` | `data` | журнал, состояние, архив счетов |
| `Y360_ORGS_FILE` | `config/orgs.json` | файл с организациями |
